## x86_64 Linuxのシステムコール
> x64アーキテクチャのLinuxにおいて、システムコールを呼び出す作法（ABI: Application Binary Interface）は非常にシンプルです。覚えるべきルールは主に以下の2つだけです。

1. `rax` レジスタに「システムコール番号」を入れる

    OSに対して「今回は〇番の仕事をお願いします」と伝えるための番号です。例えば、書き込み（`write`）のシステムコール番号は `1` です。

2. 引数を決まったレジスタに順番通りにセットする

    関数に引数を渡すのと同様に、システムコールにも引数が必要です。x64のLinuxでは、左から順に以下のレジスタに値を格納します。

    引数位置 	使用レジスタ
    syscall番号 rax
    第1引数 	rdi
    第2引数 	rsi
    第3引数 	rdx
    第4引数 	r10
    第5引数 	r8
    第6引数 	r9
    戻り値 	    rax

そして準備が整ったら、`syscall` という専用の命令を実行します。これだけで、CPUがカーネルモードに切り替わり、指定した処理が実行されるのです。

> x86アーキテクチャのレジスタ名が呪文のように不規則なのは、「40年以上前の16ビットCPU時代からのツギハギ（後方互換性）」を維持し続けているからです。

最初から綺麗に設計されたモダンなCPU（ARMやRISC-Vなど）は r0, r1, r2... のように単純な連番ですが、Intel/AMDのx86系は以下の歴史的背景が絡み合っています。
1. 名前の由来（16ビット時代の役割）

1978年のIntel 8086時代、各レジスタには「専用の役割」があり、その英単語の頭文字が名前に付けられました。

    RAX (Accumulator): 計算結果を蓄積するメインのレジスタ。だからシステムコール番号や関数の「戻り値」は必ずここに入ります。

    RDX (Data): RAXを補助するデータ保持用レジスタ。

    RSI (Source Index): 文字列やメモリ操作時の「読み取り元」アドレスを示すレジスタ。

    RDI (Destination Index): メモリ操作時の「書き込み先」アドレスを示すレジスタ。

2. 頭文字「R」の意味（ビット拡張の歴史）

時代が進みCPUが進化するたびに、元の名前を維持したまま頭文字を足してサイズを区別してきました。

    16ビット時代: AX, DI, SI

    32ビット時代: EAX, EDI, ESI （Extended ＝ 拡張）

    64ビット時代: RAX, RDI, RSI （Register ＝ 64ビットレジスタを示す接頭辞。AMDが命名）

3. 突然現れる「R8, R9」（64ビットでの追加組）

r8, r9, r10 といった連番のレジスタは、64ビット (x86_64) になった時に初めて追加された「新参者」です。

アーキテクチャを64ビットに拡張したAMDは、新しく8個のレジスタを追加する際、「もうアルファベットの頭文字を考えるのはやめて、R8〜R15という合理的な連番にしよう」と決めました。その結果、古いアルファベット組（RAX等）と新しい連番組（R8等）が混ざった奇妙な状態になりました。

    なぜ第4引数は突然「R10」になるのか？
    通常のC言語の関数呼び出しでは、第4引数には RCX (Counter) というレジスタを使います。しかしシステムコールを発行する syscall 命令は、ハードウェアの仕様上、元のプログラムの復帰アドレスを自動的に RCX に上書きして破壊してしまうという厄介な特徴を持っています。
    そのため、システムコールの引数が消えてしまわないよう、一時的な避難先として R10 を身代わりに使うという変則的なルールになっています。

# gccのオプションについて


- -E: マクロの展開や#で始まる行の処理、コメントの削除といったプリプロセスを行う
- -S: アセンブリを出力
- -c: オブジェクトファイル(機械語)の出力
- -o: オブジェクトファイルから実行ファイルのリンクを行う

- -O0: 最適化を無効化します（デフォルトですが明示的に付けると安心です）。Cのコード構造がそのままアセンブリに直訳されるため、最初はこの状態から学ぶのが基本です。
- -fno-asynchronous-unwind-tables: .cfi_ から始まるスタック展開用のデバッグ情報を抑制します。これが一番ノイズを減らしてくれます。
- -fno-ident: コンパイラのバージョン情報などを出力しないようにします。
- -fverbose-asm: 出力されるアセンブリコードの中に、「どの変数がどのレジスタ・メモリに割り当てられたか」や、「対応するC言語のコード」をコメントとして付与してくれます。Cコードとアセンブリの対応関係を追うのに最適です。

- -masm=intel: Intel記法で書く

## includeのパスについて
(Claude Opus 5)

### 1. 自分の環境の検索パスを見る

```sh
echo | gcc -xc -E -v - 2>&1 | grep -A20 'search starts here'
```

### 2. 実際にどのファイルが読まれたか見る

```sh
echo '#include <stdio.h>' > t.c && gcc -H -E t.c > /dev/null
```

### 3. パスを追加して挙動が変わることを確認する

```sh
mkdir -p mylib && echo '#define HELLO 1' > mylib/hello.h
echo '#include <hello.h>' > t2.c
gcc -E t2.c                  # エラーになる
gcc -E -Imylib t2.c          # 通る
```
